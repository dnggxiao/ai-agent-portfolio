# Featured Case Study

## 01. 四平台统一财务报表与对账系统

**企业真实业务中使用 · 项目负责人 / 工作流设计**  
**WB (Wildberries) · Amazon · Mercado Libre · Walmart**

四个平台有不同的原始数据、费用字段和结算逻辑。我把原本分散的月度财务操作重新整理为一套统一工作方式：

```text
四平台原始数据
      ↓
平台数据解析
      ↓
统一人工补充 / 调整输入
      ↓
校验 → 映射 → 核算 → 费用归集
      ↓
对账与异常检查
      ↓
统一标准财务输出
```

### 为什么这个项目重要

真正困难的不是“让 AI 算 Excel”，而是先把业务标准化。

- 四个平台保留各自真实的数据来源和结算结构；
- 财务人员需要人工提供的成本、映射和调整，被统一为明确的输入标准；
- 计算、费用归集和对账按照既定规则执行；
- 缺失成本、未知费用、SKU 未匹配等问题不会被静默忽略；
- 最终交付采用统一报表标准，减少每个平台、每个月重复解释表格结构的工作。

系统使用 **DRAFT → FINAL** 质量门：异常未解决时保持草稿，完成必要检查和对账后才进入最终输出。

原端到端人工流程涉及约 **15 个财务工作日/月**。这是原流程工作量，用于说明自动化覆盖的问题规模；不是第三方审计后的净节省工时，也不虚构效率百分比。

### 我负责什么

**我负责：**理解财务现场、业务规则拆解、四平台输入结构、统一人工输入标准、标准输出、异常策略、验收条件、边界测试、报表核对和反馈迭代。

**AI / Codex 协助：**代码实现、重构、调试和开发效率提升。模型生成的代码不是验收标准，业务结果才是。

## 我的工作方法

**理解现场 → 标准化输入 → 写清业务规则 → 定义异常 → AI 辅助实现 → 边界测试 → 人工对照 / 对账 → 标准交付 → 使用反馈迭代**

我尤其关注六件事：

- **不猜数据：**缺失成本、未知字段、未核实联系方式必须显式出现；
- **异常优先：**正常路径自动跑，模糊和异常情况交给明确规则或人工确认；
- **结果可检查：**报表、来源、公式、金额和状态应能回查；
- **允许恢复：**长批次、中断、误导入不能让整个流程从头再来；
- **标准输入输出：**自动化能否长期使用，首先取决于接口是否稳定；
- **AI 是开发工具：**我不会把模型生成内容本身当成正确结果。
